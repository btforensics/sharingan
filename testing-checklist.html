Sharingan — Sample Testing Checklist

Feed one sample per route, check the output against the expected result, log pass / fail / gap. Progress saves in your browser.
How to use. For each row: source a sample (paste the VT Intelligence query into VirusTotal Enterprise → Search, or use the other Source), run ./triage.sh <sample> (add --deep / --unpack where noted), then /analyze-sample. Compare the artifacts/report to the Expected result and set the status. A gap (amber) is a correct honest result (the tool couldn't reach it and said so) — not a failure. A fail (red) is a wrong/missing output worth fixing; capture which artifact was wrong in the notes.
VT Intelligence syntax. Queries are starting points — VT's type: / tag: / engines: values vary across the corpus and evolve over time, so adjust as needed. Useful add-ons: p:5+ (≥5 detections), ls:30d+ (seen in last 30d), have:behaviour (a sandbox report exists), fs:2024-01-01+ (first-seen). Rows marked craft have no clean VT query — generate them locally (some are already in samples/).
Safety. These are live malware. Handle in an isolated VM/network, keep samples zipped + password-protected (infected) at rest, and never click recovered URLs. Sharingan itself is static (never executes the sample), so collection is safe — the risk is mishandling the file on disk.
