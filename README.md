# Sharingan — Malware Triage Assistant

> *See through the disguise.* AI-assisted, file-type-agnostic malware triage for IR/DFIR analysts.

**Developed by Buddy Tancio.**

Sharingan runs a battery of static analysis tools over a sample (`triage.sh`),
then an AI analyst (the `/analyze-sample` Claude Code skill) reasons across **all**
the artifacts at once to produce a prioritized, evidence-cited triage report.
It accepts PE/.NET/ELF, Office docs, PDFs, LNKs, scripts, archives, and email,
and routes each file type to the stages that fit it.

See `workflow.html` for a visual tour of the pipeline and `build-roadmap.html`
for the capability roadmap.

---

## What's in this repo (and what isn't)

This repo contains **only Sharingan's own source**: `triage.sh`, the helper tools
under `tools/*.py`, the setup/install scripts, the `/analyze-sample` skill, and the
docs. The following are **deliberately not committed** and must be set up locally
(see Bootstrap below):

| Excluded | Why | How to get it |
|----------|-----|---------------|
| `config.env` | Holds live API keys | `cp config.env.example config.env` and fill in |
| `samples/` | Live malware — never push to GitHub | Supply your own samples locally |
| `reports/` | Generated output with live IOCs | Regenerated by `triage.sh` |
| `rules/` | Large third-party rule sets | Clone (step 2) |
| `tools/pestats/` | Third-party PE-stats tool | Clone (step 3) |
| `tools/venv/` | Per-analyst Python venv | `tools/setup-env.sh` (step 4) |

## Prerequisites (system tools)

Sharingan calls these from `PATH` — on Kali they're available via the package
manager. Confirm they resolve before bootstrapping:

```bash
for t in python3 capa floss yara diec pdfid 7z binwalk curl git; do
  command -v "$t" >/dev/null && echo "ok   $t" || echo "MISSING $t"
done
```

- **capa**, **floss** — Mandiant FLARE tools (`pip install flare-capa flare-floss`)
- **yara** — `apt install yara`
- **diec** — Detect-It-Easy CLI (`apt install detect-it-easy`); provides the DIE
  engine, so the heavy `DIE-engine` source tree is **not** needed at runtime
- **pdfid**, **7z**, **binwalk** — `apt install pdfid p7zip-full binwalk`

## Bootstrap (clone → working tool)

```bash
# 1. Clone Sharingan and create your config
git clone https://github.com/btforensics/sharingan.git
cd sharingan
cp config.env.example config.env
# then edit config.env and paste your own API keys:
#   VT_API_KEY        https://www.virustotal.com/gui/my-apikey
#   ABUSEIPDB_API_KEY https://www.abuseipdb.com/account/api
#   BAZAAR_API_KEY    https://auth.abuse.ch/   (one key: MalwareBazaar+ThreatFox+URLhaus)

# 2. Fetch the rule sets into rules/
mkdir -p rules
git clone https://github.com/mandiant/capa-rules.git    rules/capa-rules
git clone https://github.com/Yara-Rules/rules.git       rules/yara-rules
git clone https://github.com/Neo23x0/signature-base.git rules/signature-base
# capa FLIRT signatures (used by `capa -s`):
git clone --depth 1 --filter=blob:none --sparse https://github.com/mandiant/capa.git /tmp/capa-src
git -C /tmp/capa-src sparse-checkout set sigs && cp -r /tmp/capa-src/sigs rules/capa-sigs

# 3. Fetch the pestats helper
git clone https://github.com/as0ni/pestats.git tools/pestats

# 4. Build the per-analyst Python venv
#    (oletools / LnkParse3 / extract_msg / Speakeasy / configextractor-py + parser packs)
bash tools/setup-env.sh

# 5. (Optional) Install Ghidra for the --deep decompilation stage
sudo bash tools/ghidra/install-ghidra.sh
```

> **Note on YARA rules:** `Yara-Rules/rules` is no longer maintained upstream.
> It still matches usefully but its signature base is dated — weight a "no YARA
> match ⇒ clean" inference accordingly. `signature-base` (Neo23x0) is the actively
> maintained set.

## Usage

```bash
# Run the static-analysis pipeline over a sample (writes reports/<name>_<timestamp>/)
./triage.sh samples/suspicious.bin

# Optional deeper stages:
./triage.sh samples/suspicious.bin --deep     # + Ghidra headless decompilation (slow)
./triage.sh samples/suspicious.bin --unpack   # + Speakeasy emulation unpacking (PE only)
```

Then, in Claude Code from this project directory:

```
/analyze-sample suspicious.bin
```

The skill reads every artifact in the report dir, reasons across them, and writes
`analysis_report.md` plus a styled `analysis_report.html` deliverable into the
report directory. With no argument, `/analyze-sample` lists `samples/` and asks
which to analyze.

---

## Safety

These are live-malware artifacts. Keep `samples/` and `reports/` local, never push
them, and defang live indicators (`hxxp://`, `1.2.3[.]4`, `evil[.]com`) in any
report you share. See `CLAUDE.md` for the full handling rules the AI analyst follows.
